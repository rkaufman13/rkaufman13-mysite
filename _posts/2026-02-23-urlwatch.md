This is the sequel to my post about [automating recurring tasks with anacron]({{site.baseurl | relative_url}}{% link _posts/2026-02-02-automating-the-easy-way-with-anacron.md%}).

Say you want to keep an eye on a website and be notified when it changes. For example, maybe you are an artist waiting to see when a gallery posts a new open call for entries, or a software engineer interested in seeing when a conference opens its CFP. There are many commercial tools available for this (as well as some non-commercial ones), but why use something that's battle-tested when you can roll your own?

All joking aside, "ping me when a website changes" is not a service that I feel is worth paying for nor is it complex enough to justify creating an account on someone else's service. It's simple and something I want to customize exactly the way I want, and that is a perfect use case for building one's own solution.

Side note: All credit goes to my husband for this one, who had the idea and did the initial setup, for his own use. The only credit I get is for talking about it publicly.

Okay, so we've set up `anacron` as described [in the previous post]({{site.baseurl | relative_url}}{% link _posts/2026-02-02-automating-the-easy-way-with-anacron.md%}). Or we can just use `cron` or `launchd`, it really doesn't matter.

Now we need to install [`urlwatch`](https://github.com/thp/urlwatch) and perform one-time setup by running `urlwatch` once.

Next, run `urlwatch --edit` to add a list of URLs to watch to a YAML file.

Each URL you want to watch includes a name, an action, and a list of features:

```yaml
name: Grace Hopper
navigate: https://ghc.anitab.org/
filter:
  - html2text
  - strip
```

This says, every time URLWatch is run, navigate to that URL, convert the HTML to text, then remove leading and trailing whitespace. Then, compare the output to the previous version of the page, and if it's changed, notify me.

There are more powerful filters, although I think the most useful ones are:

- `element-by-class:` Get all HTML elements by class

- `element-by-id`: Get an HTML element by its ID

- `element-by-style`: Get all HTML elements by style

- `element-by-tag`: Get all HTML elements by a tag

- `grep`: Filter only lines matching a regular expression

So I create all the configs for URLs I want to watch, but what does it mean to "notify me"? We will configure that next.

Run `urlwatch --edit-config` to declare what this means.

By default, `urlwatch` has one "reporter" turned on, which is that it prints to stdout when the program is run. Not very helpful if I've automated it to run overnight. You can configure other reporters in the YAML opened up with the `--edit-config` flag. Some example reporters include:

- send a message to a Slack channel
- send a message to a Discord channel
- send an email
- send to IFTTT
- run a shell script

Configuring each of these will be different, but for example, for Slack, you'll create a Slack app, enable incoming webhooks, and paste the webhook URL into your urlwatch config. For IFTTT, you would add your IFTTT api key, etc. You can even configure it to send via gmail, but as the docs say, [please don't do this with your primary email](https://urlwatch.readthedocs.io/en/latest/reporters.html#e-mail-via-gmail-smtp).

Once you've configured your 'reporters' you're essentially done. Run `urlwatch --test-reporter {name of reporter}` to send a test notification. If it worked, we just add `urlwatch`, with no arguments, to our job scheduler (cron or anacron). And there you go. An easy way to keep an eye on conference CFPs, or any other page that doesn't provide RSS or an email newsletter. Enjoy!
